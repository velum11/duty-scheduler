# Duty Visual Critique — Evals

`duty-visual-critique` 스킬의 문서 기반 평가 케이스. 실행 하니스는 두지 않는다 —
검토자가 에이전트 산출을 읽고 관찰 가능한 체크리스트로 채점한다. 각 케이스는 네 항목:
시나리오 / 입력(사용자 요청 원문) / 기대 행동(관찰 가능한 항목만) / 실패 판정 기준.

---

## Case 1 — 구현된 화면의 정성 시각 검수

**시나리오**
구현이 끝난 workops 실화면 하나에 대해 시각 정성 검수를 요청받는다. 라이브 DOM과
스크린샷 관찰이 가능한 상태다.

**입력 (사용자 요청 원문)**
> "방금 구현한 근무 배정 화면 시각 검수 좀 해줘. 전문적으로 보이는지, 아니면 개발자가
> 대충 만든 것처럼 보이는지 봐줘."

**기대 행동 (관찰 가능)**
- [ ] 판정을 핵심 기준 문장("잘 만들었다 vs 개발자가 만든 화면")으로 시작하고 squint test를
      적용한다.
- [ ] 7축 루브릭(레이아웃·타이포·색/대비·시각 위계·컴포넌트 일관성·인터랙션 상태·반응형)을
      따라 점검한다.
- [ ] 각 finding에 DOM/computed-style 수치 또는 vision 관찰 증거를 붙이고, 증거 없는 항목은
      "주관 인상"으로 격하 표기한다.
- [ ] 심각도를 High/Medium/Low 버킷으로만 분류한다.
- [ ] 산출 형식을 지킨다: 종합 인상 → High/Medium/Low findings → 잘된 점 → Top 3 Fixes.
- [ ] 색 대비 수치는 직접 산출하지 않고 pixel-qa 결과를 인용한다(중복 금지).
- [ ] 반(反)장식 원칙을 적용한다 — hero·장식 카드·그라데이션·불필요 애니메이션·과대 여백·
      실데이터 없는 장식 차트를 위반으로 기록한다.
- [ ] 확인 못 한 뷰포트/상태는 "미검증"으로 표기한다.

**실패 판정 기준**
- X/10 같은 종합 점수를 산출한다.
- 증거 없는 인상을 확정 finding처럼 제시한다(주관 인상 격하 없이).
- 색 대비 수치를 직접 측정하거나 사용성·데이터 계약 영역까지 침범한다.
- 사용자 실브라우저 sign-off를 대체한다고 주장하거나, dark-mode 대비를 점검 대상에 넣는다
      (본 제품은 라이트 전용 출하).
- 비밀·개인정보·실데이터를 캡처나 산출에 포함한다.
