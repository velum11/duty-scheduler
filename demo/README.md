# WorkOps MES 목업 — Streamlit 판정 데모

```bash
streamlit run demo/app.py
```

`docs/mockup/WorkOps 최종 목업.dc.html` 을 Streamlit 으로 어디까지 재현할 수 있는지
셸 + 4화면으로 실측한 결과다. **운영 앱과 완전히 분리돼 있고 DB 를 붙이지 않는다.**

| 화면 | 유형 | 왜 이 화면인가 |
|---|---|---|
| 근무 현황 | DASHBOARD | 지표 표 + 명단 표. 밀도 시험 |
| 근무표 편성 | MATRIX_EDIT | 31일 격자 · sticky 신원 열. **가장 어려운 화면** |
| 사용자 관리 | EDIT_GRID | 기준정보 12열 표 |
| 아차사고 등록 | FORM_ENTRY | 표가 없는 화면 — 진짜 위젯만으로 되는지 |

근무표 편성·사용자 관리에는 **`표 렌더 방식` 토글**이 있다. 같은 화면을 `HTML`(목업
픽셀 재현, 읽기 전용)과 `AgGrid`(편집 가능, iframe)로 번갈아 그려 직접 비교한다.
나머지 메뉴는 사이드바 동작 확인용 자리표시자다.

## 결과 2 — AgGrid 로 바꾸면 무엇을 잃는가 (편집판)

**같은 화면, 같은 데이터, 토글만 바꿔 계측했다.**

### 글꼴 — iframe 은 부모의 웹폰트를 받지 못한다

같은 문자열(`데코코팅생산팀 2021110120 김의겸`), 같은 12.5px, 같은 font stack:

| | 폭 |
|---|---|
| 부모 문서 (Pretendard 적용됨) | **180.53px** |
| AgGrid iframe (맑은고딕으로 폴백) | **202.57px** |
| **차이** | **+22.04px = 12.21%** |

교차검증 — iframe 안에서 `'Pretendard Variable'` 지정 폭(189.93px)이
**존재하지 않는 폰트 지정 폭과 완전히 같다.** 즉 폴백이지 로드가 아니다.

`custom_css` 는 `{선택자: 속성}` 사전이라 `@font-face`·`@import` 를 실을 수 없고,
`st_aggrid` 에 임의 CSS 를 iframe 에 넣는 API 가 없다. **구조적으로 막힌다.**
→ 유일한 회피는 앱 전체를 시스템 폰트로 내리는 것(= 목업 타이포를 버리는 것)이다.

이 값은 `DESIGN.md` §7.2-23 의 기록(부모 115.93 / 표 123.76)과 같은 현상이며,
원인을 "iframe 이 웹폰트를 못 받는다"로 확정한다.

### 나머지 손실

| 목업 요구 | AgGrid | 이유 |
|---|---|---|
| 2줄 날짜 헤더 (`10` 위 / `월` 아래) | ❌ **31개 중 17개 헤더 잘림**(`10…`) | `headerComponent`(JsCode) 필요. `views/master/grid.py:255` — 배포 환경에서 JsCode 미실행 |
| 셀 칩(테두리 있는 작은 상자) | ❌ 색 글자만 | `cellRenderer` 필요. 같은 이유 |
| 주말 헤더 색(토 파랑 · 일 빨강) | ❌ | 같은 이유 |
| 열이 표 폭을 채움 | ❌ 우측 **131px** 빈 공간 | 고정 폭 열 합 < viewport |
| 행 높이 · 헤더 높이 29px | ✅ | |
| **셀 편집 · 정렬 · 체크박스 선택** | ✅ | HTML 판에는 없는 것 |

즉 **HTML 판은 예쁘고 죽어 있고, AgGrid 판은 살아 있고 이질적이다.** 둘 다 목업이 아니다.

## 결과 3 — 작업 중 드러난 Streamlit 제약 3가지

### ① `st.html` 은 웹폰트를 넣을 수 없다 (신규 발견)

`st.html()` 에 `<link rel=stylesheet>` 를 주든 `<style>@import ...</style>` 를 주든
**둘 다 제거된다.** 주입 후 문서의 Pretendard `@font-face` 규칙 0건, 그리고
Pretendard 지정 폭 == 미설치 폰트 지정 폭(189.93px).

`st.markdown(..., unsafe_allow_html=True)` 로는 들어간다. 그런데 그 경로는
**빈 줄마다 CSS 가 잘려** 텍스트로 새어나온다(마크다운 파서가 HTML 블록을 빈 줄에서
끊는다 — 실제로 이 데모의 첫 실행이 그렇게 깨졌다).

→ 결론: **폰트는 legacy 경로에 한 줄로, 나머지 CSS 는 `st.html` 로.** 두 API 를 섞어야 한다.
`demo/ui.py::inject_css` 상단에 그 조합이 있다.

### ② Streamlit 컬럼은 좁아지면 줄어들지 않고 넘친다

조회조건 4칸이 1366px 폭에서 오른쪽으로 삐져나갔다. 컬럼은 **비율만** 받고
"모자라면 접는다"는 개념이 없다 — 목업의 `62px 라벨`·`132px 라벨 셀`·`max-width:860px`
같은 px 고정도 표현할 수 없다. 목업의 `repeat(auto-fit, minmax(230px,1fr))` 에
맞추려면 `flex:1 1 230px` + 바깥 줄에만 `flex-wrap:wrap` 을 직접 걸어야 한다.
**자세한 계측과 조치는 아래 §결과 4** — 처음 시도에서 실제로 버튼이 겹쳤다.

### ③ 1.59 가 selectbox 를 react-aria 로 교체했다 — 운영 앱 CSS 가 죽어 있다

실렌더 전수 조회: `document.querySelectorAll('[data-baseweb]').length === 0`.
따라서 운영 앱의 `data-baseweb="select"` 12건 · `"input"` 8건
(`modules/ui.py`, `views/common/erp/kit.py`, `views/near_miss_improvement.py`,
`views/near_miss_submit.py`, `views/work_request_handle.py`, `views/work_request_my.py`)
이 **지금 아무것도 매치하지 않는다.** 별도 과제로 분리했다.
현행 DOM 에 맞는 참고 구현이 `demo/ui.py` §6 블록에 있다.

## 결과 4 — 좁은 폭 회귀 (2026-08-21 추가 검증)

**처음 데모는 좁은 폭에서 액션 버튼이 겹치고 라벨이 잘렸다.** 사용자가 잡아 준 결함이다.

### 목업은 안 깨진다 (대조군)

iframe 으로 폭을 고정해 `근무표 편성` 화면을 계측했다.

| 폭 | 버튼 간 겹침 | 버튼 우측 넘침 | 리본 제목↔아이콘 | 가로 오버플로 |
|---|---|---|---|---|
| 1280 | 없음(5px 간격) | −29px | −738px | 0 |
| 1024 | 없음 | −29px | −482px | 0 |
| 900 | 없음 | −29px | −358px | 0 |
| 800 | 없음 | −29px | −258px | 0 |
| 700 이하 | 모바일 셸로 전환 | — | — | 0 |

목업이 버티는 이유는 두 가지 CSS 다.
`구획 제목 줄 = flex-wrap:wrap` · `조회조건 줄 = grid auto-fit minmax(230px,1fr)`.
**둘 다 "모자라면 접는다"** 이고, Streamlit 컬럼에는 그런 개념이 없다(비율만 받는다).

### 원인과 조치

| 원인 | 조치 |
|---|---|
| 전역 `stHorizontalBlock { flex-wrap:nowrap !important }` 를 걸어 뒀다 — 좁은 폭에서 접힐 길을 내가 막았다 | 폐기. 목업처럼 **구간별로** 접기 규칙을 준다 |
| 액션 버튼을 `st.columns` 로 나눴다 — 비율이라 좁아지면 글자가 잘리고 겹친다 | `btnrow_*` 컨테이너 + `flex-wrap:wrap` + 버튼 **내용 폭** |
| 조회조건 라벨을 비율(0.15)로 뒀다 — `사번·성명` 이 잘렸다 | 라벨 열 `flex:0 0 66px` 고정(목업 62px) |
| `st-key-*` 를 **자손** 선택자로 잡았다 | 그 클래스는 `stVerticalBlock` **자신**에 붙는다. 직접 지목으로 수정 |

> ⚠ 한글·공백이 든 `key` 는 `btnrow_2026-08-------` 처럼 치환된다. 부분일치로 잡아야 한다.

|---|---|---|---|---|---|
| 1440 | 1 | 5px | −24px | 없음 | 0 |
| 1366 | 1 | 5px | −24px | 없음 | 0 |
| 1280 | 1 | 5px | −25px | 없음 | 0 |
| 1100 | 1 | 5px | −25px | 없음 | 0 |
| 1024 | 1 | 5px | −25px | 없음 | 0 |
| 980 | 1 | 5px | −25px | 없음 | 0 |

버튼 간격 5px 은 목업 실측값과 같다. 800px 에서 조회조건 4칸은 목업처럼 2줄로 접히고,
라벨은 끝까지 컨트롤 옆에 남는다.

데모는 그 전환을 구현하지 않았다.
